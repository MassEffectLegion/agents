# Omega — последний рубеж восстановления

Omega работает независимо от PostgreSQL, alfa/bravo и их Python-окружений. Это отдельный долгоживущий инженер восстановления: собственная SQLite-память, файловый чекпоинт, инструменты Python/CLI/SSH и две llama-модели.

## Запуск

В этом каталоге уже подготовлены переносимый **Python 3.11.9 для Windows x64** (`runtime`) и зависимости (`vendor`). Установленный в Windows Python и интернет для запуска не нужны.

1. Остановите alfa/bravo, использующие те же серверы/слоты.
2. При необходимости отредактируйте `config.json` и `task.txt`.
3. Запустите **run_omega.bat**. Он использует собственный Python, не зависит от текущего каталога и активированного venv.
4. Лог — `logs/omega.log`. Остановить omega можно Ctrl+C.

Каталог переносим: пути вычисляются от местонахождения omega. Для другого интерпретатора можно явно задать полный путь в `OMEGA_PYTHON`. Штатный запуск из BAT изолирован от глобального `PYTHONPATH` и пользовательских пакетов.

## DENSE и MoE

В `config.json` уже указаны:

| Имя | Сервер | Роль | Слот |
| --- | --- | --- | --- |
| dense | http://127.0.0.1:8080/v1 | Основной исполнитель, Qwen 3.8 27B Q4 | 0 |
| moe | http://127.0.0.1:8080/v1 | Второй взгляд и резерв, Qwen 3.6 35B A3B Q4 | 0 |

Фактические имя модели и размер окна определяются сервером; значения в файле — fallback. Перед **новым контекстом** принудительно очищается слот используемого сервера. При ошибке очистки запрос не отправляется. Это относится и к отдельным консультациям. Omega предназначен для работы вместо остановленных alfa/bravo на этих слотах.

При `council_on_cycle_start=true` модели **одновременно** анализируют поручение и память. Основная модель получает оба мнения и выполняет действия. Инструмент `consult_models` позволяет повторить параллельную консультацию в любой момент. У консультантов нет инструментов: единственный исполнитель действий — основной цикл omega. Это предотвращает конкурирующие правки файлов/БД.

При отказе основного сервера omega пробует другой; при недоступности обоих сохраняет состояние и повторяет попытку. Отказ одной консультации не теряет ответ второй модели. Ошибка модели после выполненного инструмента приводит к новому циклу с памятью, а не к автоматическому повтору инструмента.

## Поручения без PostgreSQL

Постоянное начальное поручение можно изменить в `task.txt`. Для новых задач работающему omega используйте локальную очередь SQLite. Из каталога omega:

```bat
runtime\python.exe -I -X utf8 boot.py manage.py ask "Проверь, почему alfa не запускается. Сначала собери диагностику."
runtime\python.exe -I -X utf8 boot.py manage.py status
```

Omega подхватывает очередь между шагами, включая после рестарта. Инструмент `complete_request` сохраняет результат поручения. `manage.py` работает без llama и библиотек моделей, поскольку использует стандартную библиотеку Python и SQLite.

## Контекст и параметры

`config.json` — основной файл конфигурации, особенно адреса моделей, слоты, SQLite-путь, Python и разрешённые каталоги. Рабочие числовые параметры можно переопределять в собственной SQLite-таблице `agent_settings`:

```bat
runtime\python.exe -I -X utf8 boot.py manage.py set context_usage_percent 90
runtime\python.exe -I -X utf8 boot.py manage.py set no_tool_response_limit 2
```

- `context_usage_percent=95`: процент фактического серверного окна для всего бюджета запроса/ответа.
- `completion_max_tokens=8192`, `completion_min_tokens=1024`, `context_safety_tokens=512`: размер ответа уменьшается у границы окна. Подсчёт через `/apply-template` + `/tokenize`, fallback корректируется по фактическому usage.
- `no_tool_response_limit=2`: после первого ответа без инструментов история сохраняется; после второго подряд — новый цикл. Вызов инструмента сбрасывает счётчик.
- `settings_refresh_seconds=30`: обновление рабочих параметров между шагами. Настройки серверов применяются со следующего цикла; изменение SQLite-пути требует перезапуска.
- `council_on_cycle_start=true`, `council_max_tokens=2048`, `council_timeout_seconds=120`: параллельная консультация.
- `restart_delay_seconds=5`: пауза между циклами и перед продолжением ответа без инструментов.
- `script_timeout_max_seconds=600`: верхний таймаут синхронного Python/CLI-вызова.
- `tool_output_max_chars=12000`: большие результаты сохраняются целиком в файл, в контекст передаётся фрагмент и путь.

SQLite-переопределения имеют приоритет над файлом только для допустимых рабочих параметров; адреса моделей остаются в файле. Неверный новый конфиг не заменяет последний корректный снимок.

## Файлы и процессы

По умолчанию `extra_allowed_dirs=[".."]`: файловым инструментам доступен родительский каталог omega со всеми соседними агентами. Например, при расположении `<PROGRESS_DIR>\omega` доступен `<PROGRESS_DIR>`. Для других дисков добавьте пути в JSON либо в BAT:

```bat
set "AGENT_EXTRA_DIRS=<AGENTS_DIR>;D:\backup"
```

Инструменты:

- `run_python_script`: код или существующий `.py`, аргументы, cwd, интерпретатор, таймаут. `background=true` запускает долгоживущий агент и возвращает `job_id`.
- `run_command`: явный список аргументов CLI без неявного shell — Python, pip, Git, psql и т. п.
- `status_process`, `stop_process`: вывод и управление **процессами, запущенными omega**. Перед остановкой проверяются PID и время создания, чтобы не задеть повторно использованный PID.
- `query_sqlite`: SQL к собственной памяти, по умолчанию чтение; запись требует `allow_write=true`.
- `save_progress`, `complete_request`, `backup_sqlite`, `consult_models`.
- Чтение/запись/список файлов, SSH-команды и загрузка/выгрузка SFTP.

Вывод процессов — `logs/processes`; синхронный вызов при таймауте останавливает дерево процессов. Фоновый процесс продолжает работу до собственного завершения или `stop_process`, в том числе после остановки omega. После запуска заново его можно найти в SQLite `process_jobs`. Ограничения файловых инструментов не являются песочницей: Python/CLI работают с правами запустившего пользователя, как требуется для ремонта.

Для запуска/отладки alfa или bravo указывайте их собственный интерпретатор, если он сохранён. У явно указанного интерпретатора omega не подменяет пакеты своими. Python-код, запускаемый штатным интерпретатором omega, получает доступ к локальному `vendor` через `boot.py`.

Штатный pip доступен без системной установки:

```bat
runtime\python.exe -I -X utf8 boot.py -m pip --version
```

Для восстановления PostgreSQL omega использует Python/CLI. PostgreSQL-драйвер, клиентские программы и сервер PostgreSQL не нужны для старта самого omega; при необходимости их устанавливают отдельно под задачу. Параметры чужих БД и пароли в omega не копировались.

## Память и резервные копии

- `data/omega.sqlite3`: задачи, сообщения, чекпоинты, поручения, процессы и настройки. WAL, короткие транзакции, контроль внешних ключей.
- `data/latest_checkpoint.json`: читаемая файловая копия текущего прогресса.
- `data/backups`: online backup SQLite после первого цикла и затем каждых десяти циклов. Старые резервные копии автоматически не удаляются.
- `logs/recovery.jsonl`: журнал при ошибках записи памяти.
- `logs/tool_events.jsonl`: результаты выполненных инструментов до записи в БД.
- Блокировка файла не позволяет одновременно запустить два исполняющих процесса omega на одной памяти.

Проверка, backup, export и восстановление работают **без моделей и без vendor**, только на bundled Python:

```bat
runtime\python.exe -I -X utf8 recovery.py check
runtime\python.exe -I -X utf8 recovery.py backup D:\backup\omega.sqlite3
runtime\python.exe -I -X utf8 recovery.py export D:\backup\omega.sql
runtime\python.exe -I -X utf8 recovery.py restore D:\backup\omega.sqlite3
```

Для restore omega должен быть остановлен. Сначала проверяются целостность и схема копии, затем создаётся согласованный временный файл. Прежняя БД вместе с WAL/SHM сохраняется в `data/before_restore`; неверная копия не заменит текущую память. Если БД потеряна целиком, `recovery.py init` создаст новую, а `data/latest_checkpoint.json` и файлы отчётов останутся источником восстановления.

## Развёртывание с нуля без интернета

Скопируйте **весь каталог omega** на Windows x64 и запустите `run_omega.bat`. Пути не привязаны к диску I:. Модели должны быть доступны на указанных llama-серверах; без них остаётся ручная консоль восстановления.

Если папка `vendor` повреждена или утрачена, запустите **setup_omega.bat**. Она проверяет SHA-256 и переустанавливает зависимости из `offline/wheels` без доступа к сети и без установленного pip. Комплект содержит зафиксированные версии в `requirements-lock.txt` и локальную копию pip. Исходная лицензия CPython лежит в `runtime/LICENSE.txt`, лицензии пакетов — в их метаданных.

Сохраните копию всего комплекта вместе с актуальным SQLite backup на отдельном носителе: файлы на том же неисправном диске не заменяют внешнюю копию. При утрате самого `runtime` его нужно вернуть из копии комплекта либо указать совместимый Python 3.11 x64.

## Проверки

Проверены SQLite-память/очередь, backup/restore, запрет двух экземпляров, отсутствие PostgreSQL-зависимости, фоновый Python, traceback, таймаут и остановка процессов, параллельные ответы моделей и блокировка генерации при неудачной очистке слота.

Два интеграционных теста используют **локальные имитаторы llama** и настоящий OpenAI-совместимый клиент: полный цикл с Python-инструментом, двумя ответами без инструментов, очисткой слотов и переходом на MoE при отказе DENSE. Реальные серверы пользователя при этих проверках не очищались и не генерировали ответы.

Повторить тесты:

```bat
runtime\python.exe -I -X utf8 boot.py tests\test_omega.py
runtime\python.exe -I -X utf8 boot.py tests\test_integration.py
```
